# 拾壁校园 MVP 开发计划

## 当前基线

开发分支为 `feat/campus-mvp-deepseek`，从 `main` 的 `0eb05eb037453162f3702a007f81ec5fee3ff68a` 创建。现有桌面工作流、界面和修复算法是后续实验的起点。环境、实际调用路径和本机验证结果见 [开发基线](BASELINE.md)。

## MVP 范围

用合成样本和来源、许可明确的壁画照片演示本地导入、缺损清单、逐项修补、人工复核和 ZIP 导出。基础演示采用手工缺损或掩膜、OpenCV 和规则规划，可在无模型权重和无 API 密钥时运行。具备本地模型条件后，再验收真实 Qwen3-VL 缺损分析到清单的路径。

拟议的 DeepSeek 接入点是修复建议和规划。本地视觉分析继续提供候选范围、证据和文化线索。下一阶段先查证拟选模型的输入能力和接口，再确定传入哪些字段。如果选用文本接口，优先使用经人工确认的结构化缺损条目、掩膜统计和允许的工具；用合成或公开样例验证请求和响应。当前分支基线没有 DeepSeek 专用适配或真实调用记录。

## 实现入口与验证顺序

1. 用 `tests/test_webui.py` 中的工作流用例复现桌面桥接，关注分析只生成候选、清单支持手工添加、OpenCV 候选可复核和归档。确认现有 `ui/app.js`、`mural_agent/desktop_web.py` 和 `mural_agent/defect_jobs.py` 的任务契约。
2. 从 `mural_agent/planner.py` 的 `api_plan`、`mural_agent/engine.py` 的 `Engine.make_plan` 和 `mural_agent/config.py` 的 `Settings` 开始查接口。现有视觉 API 不论选择 `/responses` 或 `/chat/completions`，都会发送原图和红色掩膜预览的缩略图。清单路径当前固定传入 `planner='rules'`，后续若要为清单显示 DeepSeek 建议，需要明确新增入口及触发条件。
3. 先用模拟响应验证请求字段、`Plan` 结构、工具白名单、步数预算、超时或格式错误后的规则回退。确认可选规划不妨碍离线修补，导出记录可追溯到实际方案来源。涉及真实服务的验收使用单独的本地配置和公开或合成测试数据。
4. 用缺损清单逐项及批量操作做一轮桌面验收，记录各任务候选、复核结论及导出状态。检查原图、掩膜、差异图及 `manifest.json`，验证未授权修改区域的像素保持一致、驳回结果受导出限制、假设性结果按对应标签归档。

## 待验证能力

- 用带来源与专家标注的样本验证真实缺损、风险分类和修补质量。当前估计值与合成图像的工程指标适用于流程验证。
- 在明确模型来源、版本、许可和目标设备后，按阶段补做真实 Qwen3-VL、LaMa CUDA，以及确有演示需求时的 SAM 或扩散验收。
- 核对校园现场演示机器的 Python、Qt WebEngine、网络和 GPU 条件。基础演示可通过内置合成示例和手工圈选复现。
